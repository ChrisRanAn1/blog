## Overview

This is a write up on the classic **many-time pad attack** — what happens when a one-time pad (OTP) key gets reused across multiple messages.

The setup: 11 plaintexts encrypted with a stream cipher, all under the **same key**. Given only the 11 ciphertexts (hex-encoded), the goal is to recover the plaintext of the last one.

The vulnerability is entirely structural — no brute force, no weakness in the cipher itself. It comes purely from key reuse.

```
OTP security proof requires: key used exactly once
Here: same key used 11 times
↓
perfect secrecy guarantee no longer holds
```

---

## 1. The Setup

The ciphertexts were generated by code equivalent to:

```python
key = random(1024)                                  # one key, generated once
ciphertexts = [encrypt(key, msg) for msg in MSGS]    # reused for all 11 messages

def encrypt(key, msg):
    msg = bytes(msg, 'utf-8')
    c = xor(key, msg)
    return c.hex()
```

Each ciphertext only consumes a prefix of `key` equal to its own length, but every message draws from the **same underlying byte sequence**. That single line — `key` generated once, reused across the loop — is the entire vulnerability.

---

## 2. Why Reuse Breaks Everything

A cipher is defined as:

```
c = k ⊕ m
```

For two ciphertexts encrypted under the same key:

```
c1 = k ⊕ m1
c2 = k ⊕ m2
```

XOR-ing them together:

```
c1 ⊕ c2 = (k ⊕ m1) ⊕ (k ⊕ m2)
        = (k ⊕ k) ⊕ (m1 ⊕ m2)
        = 0 ⊕ (m1 ⊕ m2)
        = m1 ⊕ m2
```

The key cancels out completely — `k ⊕ k = 0` — because XOR is commutative and associative and any value XORed with itself is zero.

```
attacker has:      c1, c2
attacker computes:  c1 ⊕ c2
result equals:      m1 ⊕ m2
```

No knowledge of `k` is required. XOR-ing two ciphertexts is mathematically identical to XOR-ing the two underlying plaintexts.

---

## 3. Why the Space Character Matters

`m1 ⊕ m2` alone isn't plaintext, but it isn't useless either — it leaks structure, and English text has one very exploitable structural property: **spaces are extremely common**, and they interact with letters in a specific way under XOR.

ASCII values, in binary:

```
space  = 0x20 = 0010 0000
'A'    = 0x41 = 0100 0001
'a'    = 0x61 = 0110 0001
```

Uppercase and lowercase letters differ from each other by exactly one bit — bit 5 (value `0x20`), which is also exactly the space character's only set bit. So:

```
space ⊕ letter = same letter, case flipped
letter ⊕ letter (different letters) = usually unprintable garbage
```

Example:

```
' ' (0x20) ⊕ 'a' (0x61) = 0x41 = 'A'
```

Applied to the many-time pad: at any byte position where **one** message has a space and another has a letter, `c_i ⊕ c_j` decodes to a readable (case-flipped) letter. Where both have letters, it usually doesn't.

This gives a concrete signal: **scan for positions where the XOR of two ciphertexts is printable — that position likely has a space in one of the two messages.**

---

## 4. The Attack Algorithm

Because 11 messages share the same key, the key can be recovered **one byte position at a time**. For a fixed position `pos`:

```
for each message c in the ciphertext set:
    assume c[pos] encrypts a space
    candidate_key = c[pos] ⊕ 0x20

    score = number of messages where (message[pos] ⊕ candidate_key)
            decodes to a letter or space

keep the candidate with the highest score
```

The reasoning: if the candidate key byte is correct, it should make **every** message at that position decode to something readable — because all 11 messages share the same true key. A wrong candidate only "works" for the one message it was guessed from; it is extremely unlikely to coincidentally make ten unrelated messages also decode to letters.

```python
def is_letter_or_space(b):
    return b == 32 or 65 <= b <= 90 or 97 <= b <= 122

def guess_key_byte(cts, pos):
    active = [c for c in cts if len(c) > pos]
    best, best_score = None, -1
    for c in active:
        guess = c[pos] ^ 0x20
        score = sum(is_letter_or_space(cc[pos] ^ guess) for cc in active)
        if score > best_score:
            best, best_score = guess, score
    return best

def recover_key(cts):
    n = max(len(c) for c in cts)
    return [guess_key_byte(cts, i) for i in range(n)]

def decrypt(c, key):
    return ''.join(
        chr(c[i] ^ key[i]) if 32 <= (c[i] ^ key[i]) <= 126 else '.'
        for i in range(len(c))
    )
```

Repeating `guess_key_byte` across every position reconstructs the key column by column, and decrypting all 11 ciphertexts with it falls out for free.

---

## 5. Where the Statistical Method Fails

At some byte positions, **none** of the 11 messages happen to contain a space — every candidate scores low, and the majority-vote heuristic has nothing to lock onto:

```
New Yo?k Knick?rbockers ?re the 20?6 world c?am?No?:.
```

These gaps aren't a bug in the method; they're a limit of it — the space heuristic can only surface information where a space actually occurs across the corpus. The remaining bytes are filled using English context instead of statistics:

```
Yo?k            → York
Knick?rbockers  → Knickerbockers
?re the         → are the
c?am?No?:.      → champions.
```

---

## 6. Result

```
The New York Knickerbockers are the 2026 world champions.
```

Cross-validating the recovered key segment against the other 10 ciphertexts confirms it — every other message also decodes to coherent English across the same byte range, which is strong evidence the key bytes are correct (a wrong key would not simultaneously produce readable text across 10 independent, unrelated messages).
